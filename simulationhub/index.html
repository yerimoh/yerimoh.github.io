  Why relations
  
Same goal, different path같은 목표, 다른 경로

  
An agent given only a tool list returns wrong numbers without an error. An agent given the relations fills the preconditions first and never picks a forbidden combination.도구 목록만 받은 에이전트는 에러 없이 틀린 숫자를 냅니다. 관계를 받은 에이전트는 전제 조건을 먼저 채우고, 금지된 조합은 처음부터 고르지 않습니다.

  Four kinds of relation관계 네 종류
  
Every caveat in the catalog becomes an edge카탈로그의 주의사항이 전부 선이 됩니다

  
Composition knowledge that used to live only in experienced researchers' heads, written so a machine can read it and enforced when the agent plans a path.숙련된 연구자의 머릿속에만 있던 조합 지식을 기계가 읽을 수 있게 적고, 에이전트가 경로를 짤 때 강제합니다.

  

    

    

  






  Enforced at run time실행 시점에 강제
  

    
Forbidden combinations are never on the menu금지된 조합은 선택지에 없다
Input types, preconditions and compatibility are checked mechanically by the graph, not by the LLM. A path that fails the check is not executed even if the LLM proposes it. Only the choice among remaining substitutes, and their order, is left to cost and uncertainty.입력 형식, 전제 조건, 호환성은 LLM이 아니라 그래프가 기계적으로 검사합니다. 검사를 통과하지 못한 경로는 LLM이 제안해도 실행되지 않습니다. 남은 선택지 중 어느 대체 도구를 어떤 순서로 쓸지만 비용과 불확실성을 보고 고릅니다.

    
Failures are recorded too실패도 기록으로 남는다
Every result carries a status flag: normal, a minor error that was auto-recovered, a failed run, or a silent failure where the output looks fine but is physically wrong. Combinations that produced silent failures are added to the graph as new relations, so the graph is updated as data accumulates.결과마다 상태 플래그가 붙습니다. 정상, 자동 복구된 가벼운 오류, 계산 실패, 그리고 결과는 나왔는데 물리적으로 틀린 조용한 실패. 조용한 실패를 낸 조합은 새 관계로 그래프에 추가되므로, 그래프는 데이터가 쌓이면서 갱신됩니다.

  About
  
Why build it왜 만드나

  
Materials-simulation tools already exist in abundance, and hundreds of wrappers expose them to agents. What is missing is the knowledge of how to combine them. Written down as four kinds of relation, that knowledge lets an agent compose tools in the right order and with the right settings without a human, and running those compositions at scale produces the data needed to learn a world model of the materials world. SimulationHub is the first step of the MatWorld proposal. It does not claim the relations are complete; it aims to show on benchmarks that having them beats not having them.재료 계산 도구는 이미 충분히 많고, 그것을 에이전트에 노출한 래퍼도 수백 개가 있습니다. 비어 있는 것은 도구를 조합하는 지식입니다. 그 지식을 네 종류의 관계로 적어 두면 에이전트가 사람 없이도 도구를 올바른 순서와 설정으로 조합할 수 있고, 그 조합을 대량으로 돌려 재료 세계의 월드모델을 학습할 데이터를 만들 수 있습니다. SimulationHub는 MatWorld 제안의 첫 단계이며, 관계가 완전하다고 주장하지 않고 관계가 있으면 없을 때보다 낫다는 것을 벤치마크에서 보이려 합니다.

  
The survey covered three strands: MCP servers, SKILL.md skill packs, and non-MCP platforms, benchmarks and standards. Entries were verified on GitHub, through PyPI and npm metadata, and in arXiv and official docs; about 30 skill packs were cloned and counted. Items that could not be opened are marked [unverified]. Except for phonopy, the tool specs on this page had no complete spec in the source and were filled from general documentation.조사는 MCP 서버, SKILL.md 스킬팩, MCP가 아닌 플랫폼과 벤치마크와 표준의 세 갈래로 했습니다. GitHub, PyPI와 npm 메타데이터, arXiv와 공식 문서를 열어 확인했고 스킬팩 30여 개는 저장소를 클론해 셌습니다. 열지 못한 항목은 [미검증]입니다. 이 페이지의 도구 명세 중 phonopy 외에는 원문에 완전한 명세가 없어 일반 문서 기준으로 채웠습니다.
